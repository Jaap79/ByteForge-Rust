# ByteForge Rust architecture

Fork baseline: ByteForge FASM 1.0.0.10, commit a401721. Rust edition 1.1.0 targets native Windows x64. The original assembler and executable are retained under `legacy/`; no FASM files are required at Rust runtime.

## State ownership

`Document` owns normalized Unicode text, disk identity, dirty state, encoding/EOL and appearance. Each live `Tab` owns a separate RichEdit HWND and HFONT; native RichEdit retains per-tab undo/redo during the process. Tab reordering moves the whole `Tab`. Switching does not copy plain text through a shared control and therefore retains native formatting/undo.

The UI thread owns `App` through a thread-local RefCell. Reentrant native notifications use `try_borrow_mut`; paint/menu helpers and control subclasses can operate independently. Programmatic edits explicitly update capture state because reentrant EN_CHANGE is suppressed. User EN_CHANGE marks a tab for capture. UTF-16 CP positions are used at the FFI boundary; document paragraphs use one LF, matching RichEdit's one paragraph CP. Search line/column calculation uses document text, independent of wrap layout.

`native.rs` is the raw FFI/theme/dialog boundary. `ui/mod.rs` owns document commands, tab/search presentation and the Win32 message loop. `platform.rs` performs the explicitly requested Rust update query on a background thread and opens only the fixed GitHub repository URL in the default browser. No network action occurs on startup.

## Persistence

The BFRSESS2 binary format is length-prefixed and checksummed with CRC-32 (corruption detection, not authentication). It adds one bounded context byte per tab after the hex-view byte. Legacy BFRSESS1 snapshots are read with Plain text as their context; old executables cannot read BFRSESS2. It preserves Windows path UTF-16, Unicode text and document settings. Decoder bounds: 128 tabs, 32 MiB text per document, 128 MiB snapshot, valid setting ranges and ordered non-overlapping highlight spans. Unknown/truncated/trailing/corrupt input is rejected. CRC does not make a snapshot trustworthy; parsing is bounded regardless.

Snapshot files are flushed then replaced atomically using ReplaceFileW/MoveFileExW. Before replacing the current valid session, its bytes are atomically saved as the previous snapshot. Corrupt current files never replace a good backup. If both snapshots are unusable, automatic writes pause. The user's files are never overwritten during recovery. Normal exit with recovery enabled must successfully snapshot before closing. Crash recovery can lose the most recent 1.5-second interval; hard power-loss durability depends on Windows/storage flush guarantees.

SHA-256 of the last opened/saved disk bytes is persisted independently of buffer text. A changed/deleted source file requires a decision before save. Save As refuses a path owned by another tab. Atomic document writes preserve the old file when replacement fails. Format settings remain session metadata; plain text remains plain text.

An exclusive file handle with share mode 0 prevents two processes from writing one session directory. Recovery OFF is remembered by an explicit marker; clearing recovery removes only the two known snapshot files, never recursive directories or user documents. Recovery files contain readable text under the current user's profile.

## Interface

The hex viewer owns a separate 9pt Consolas HFONT rather than borrowing a tab's editor font handle. EN_CHANGE coalesces a deferred REFRESH_HEX message so text is captured after native editing completes; capture also refreshes after programmatic changes such as undo and replace. Cached preview text avoids resetting selection/scroll when encoded bytes have not changed. Pane width and monospace metrics select 4/8/16 bytes per row. Editor/hex headers and an 8px scaled divider separate the panes, and empty search results do not reserve an unused panel.

Font application explicitly reapplies theme foreground after WM_SETFONT/CHARFORMAT changes. Dark-mode highlights use deeper rendered backgrounds paired with their unchanged logical session color; capture normalizes both theme variants back to that logical color. This keeps all editor text light in dark mode and dark in light mode without changing the recovery file schema.

The shared Jaap palette has semantic roles for dark/light surfaces, text, borders and accent. Native title bars are themed via DWM. Menus are owner-drawn while retaining labels/access keys. The native TabControl keeps its accessibility and hit testing; a subclass paints its full surface and per-tab color stripe. Checkbox painting preserves native toggle/keyboard semantics. DPI changes rebuild fonts and control sizes. Each theme change redraws the full child tree.

WM_SETREDRAW restores WS_VISIBLE; highlight snapshotting and theme helpers explicitly preserve prior visibility so hidden editors stay hidden. This has a native UI regression check.

## Syntax and tab movement (1.2.0)

`src/syntax.rs` is a dependency-free, error-tolerant lexer with UTF-16 token spans and cached incoming/outgoing lexical state per line. Changed text is compared against the cached prefix/suffix; only changed lines and state-dependent successors are lexed. JSON property lookahead includes intervening blank lines. JSON key reclassification truncates only the current token's spans instead of repeatedly scanning the whole output. Line and token span lookups use partition points.

As of 1.2.2, `src/ui/syntax.rs` maps the left/right edge of each visible screen row to independent CP ranges, excluding long offscreen tails between rows. Sampling is pixel-based rather than inferred from the base font, because rich-pasted text can have mixed font sizes. TOM `ITextDocument::Range`/`ITextFont` foreground access never moves the editor selection. Adjacent equal-color runs are merged, unchanged foregrounds skipped, and runs with mixed manual backgrounds split so manual marks retain priority. At most 256 runs or about 8 ms of formatting are performed per message; pending work continues through `SYNTAX_VIEW`. View/revision/theme changes discard stale queued runs. Each batch freezes/unfreezes native display and restores scroll, modified bit and event mask. RichEdit TOM `ITextDocument::Undo(tomSuspend/tomResume)` excludes decoration from undo/redo without clearing the buffer. First lexical analysis remains synchronous and linear after the 120 ms typing debounce; there is no interpreter, subprocess, network or external grammar.

Rich paste retains the existing `WM_PASTE` behavior. Plain paste requests `CF_UNICODETEXT` through `EM_PASTESPECIAL`, normalizes only the inserted range to the tab's font/size and theme, clears inherited character effects/backgrounds, then restores the insertion caret. `ITextDocument::BeginEditCollection/EndEditCollection` groups those changes into one undo action, distinct from syntax decoration's undo suspension. The session format remains BFRSESS2: this is a text editor, not an arbitrary rich-text file/recovery format.

PowerShell token roles follow [Microsoft PSReadLine's categories](https://learn.microsoft.com/en-us/powershell/module/psreadline/set-psreadlineoption?view=powershell-7.5), with parsing informed by [argument/expression mode](https://learn.microsoft.com/en-us/powershell/module/microsoft.powershell.core/about/about_parsing?view=powershell-7.5) and [quoting rules](https://learn.microsoft.com/en-us/powershell/module/microsoft.powershell.core/about/about_quoting_rules?view=powershell-7.5). JSON display categories follow [RFC 8259](https://www.rfc-editor.org/info/rfc8259/). This implementation deliberately does not claim full AST/semantic equivalence to PowerShell or schema validation. The [TOM undo contract](https://learn.microsoft.com/en-us/windows/win32/api/tom/nf-tom-itextdocument-undo) and [Microsoft's TOM header](https://github.com/microsoft/win32metadata/blob/main/generation/WinSDK/RecompiledIdlHeaders/um/TOM.h) document the native ABI boundary.

Native tab mouse capture records the source, movement threshold and destination; the parent receives a deferred reorder command after release. The whole `Tab` is removed/inserted, the active HWND is located by identity, all other editors are explicitly hidden and the active editor/hex/layout are repainted. No document is copied through another RichEdit. The plus is a separate accessible owner-drawn button above the blank area of the full-width native tab control; sibling clipping prevents overpainting and avoids false overflow caused by shrinking the control.

## External file launches (1.2.1)

The exclusive `session.lock` remains authoritative. On Windows sharing/lock violations only, a normal secondary launch resolves its file paths against the caller's working directory, locates the same-desktop primary window by a property derived from the canonicalized, case-normalized session directory, and sends a bounded `WM_COPYDATA` request. Other session I/O failures are reported as such, not mistaken for an existing instance. Endpoint lookup tolerates five seconds of startup; `SendMessageTimeoutW` waits at most five seconds for acknowledgement. The receiver validates a version marker, count, flags, absolute UTF-16 path lengths, NULs, total size and trailing bytes, copies the paths into a bounded queue and acknowledges without doing file I/O or showing a prompt in the sender's synchronous call.

The deferred main-window handler opens files through the existing `App::open` implementation. Requests received while `App` is borrowed or a modal owner is disabled stay queued; the main timer retries them. Shutdown drains pending requests before snapshotting. The sender grants foreground permission only to the discovered process; the receiver restores a minimized window for interactive launches. Hidden test launches do not display the receiver. Workspace selection and Win32 desktop/UIPI restrictions are preserved; this is not an elevated file-open broker or a security boundary against another process running as the same user. It opens plain-text files only and does not interpret incoming text as commands. No file association is written.

`src/instance.rs` owns endpoint lookup, bounded message encoding/decoding, relative-path resolution and the pending queue. `tests/explorer-open.ps1` starts actual independent executable processes, verifies handoff/exits and then forcibly restarts each private workspace to inspect restored live editor contents. This tests the Explorer-style process-launch path without changing the machine's associations or touching user sessions. API references: [WM_COPYDATA lifetime/copying](https://learn.microsoft.com/en-us/windows/win32/dataxchg/wm-copydata), [bounded SendMessageTimeout](https://learn.microsoft.com/en-us/windows/win32/api/winuser/nf-winuser-sendmessagetimeoutw), [foreground permission](https://learn.microsoft.com/en-us/windows/win32/api/winuser/nf-winuser-allowsetforegroundwindow).

## Tests

### Manual update checks and spacing (1.2.3)

The tab strip's top and bottom padding each increase by 4 logical pixels, preserving its existing tab-item height, plus target and overflow layout. Find/replace controls move with that offset. The status STATIC uses a 30-logical-pixel height and `SS_CENTERIMAGE`; editor/results/hex bounds reserve that height. Existing palette brushes paint all gaps without extra system borders.

Help/Ctrl+U starts one worker, disables duplicate checks and polls its bounded result without blocking the message loop. WinHTTP reads the public `raw.githubusercontent.com/Jaap79/ByteForge-Rust/main/Cargo.toml` over certificate-verified HTTPS with automatic system-proxy selection, 5-second phase timeouts, a 15-second elapsed check between reads and a 32 KiB response cap. Redirects are refused. `src/update.rs` parses only the simple quoted `[package]` version and compares numeric components; dependency versions, malformed/duplicate versions and prerelease syntax are rejected. Three/four-component numeric versions normalize to four components for comparison. Failed or disconnected workers never imply the app is current. The reference is the distributed `main` version, not a GitHub Release/prerelease channel.

About/update dialogs expose a native owner-drawn, tab-focusable link button with underlined theme-readable text, hand cursor and focus indication. The only navigation target is the compiled-in GitHub repository URL; response text cannot choose a URL or execute a command. Opening the browser is user-initiated; no installer, token, new dependency or separate public feed is needed. API reference: [ShellExecuteW](https://learn.microsoft.com/en-us/windows/win32/api/shellapi/nf-shellapi-shellexecutew).

Unit tests cover Unicode/encoding/EOL round trips, strict input rejection, session corruption/truncation, backup fallback, known hash vectors, atomic save and external-file conflicts. The storage test locks the destination and proves a failed replacement neither truncates it nor leaves temporary files. Native tests cover actual RichEdit selection/highlight/zoom, tab settings, search in hidden wrapped tabs, save, undo/redo, replacing, snapshots and process-termination/restart recovery. GUI QA also inspects dark/light native chrome, menus, search, tabs and dialogs.
